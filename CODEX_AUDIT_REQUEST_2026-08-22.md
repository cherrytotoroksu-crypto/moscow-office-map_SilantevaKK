RECHECKED`). Все пункты ниже — находки Claude Code за сессии 2026-08-18 —

## Правила

Те же, что в `QA_COORDINATION.md`: не чинить по ближайшей точке при
расхождении имени/адреса/координат, не сливать сущности без минимум двух
независимых подтверждений.

`data/building_dates.json` — по умолчанию не менять никому. **Разовое
исключение 2026-08-22**: пользователь явно снял запрет для Claude Code на
одну задачу (поиск дат ввода/старта продаж/начала стройки для уже
известных пробелов) — см. `outputs/classifier_11_records_review_2026-08-19.md`,
раздел «Обновление 2026-08-22 (второй заход)». Запрет **не снят в общем
виде** — для любой другой правки файла нужно отдельное разрешение.

**Новое, 2026-08-22**: см. `CONSTRUCTION_STAGE_RETROSPECTIVE_SPEC_2026-08-22.md`
— план по историзации стадий стройки по кварталам (отдельная сущность
`stage_observation`, не замена `building_dates.json`). Реализация не

должны быть с ним совместимы — не перезаписывать даты без сохранения
предыдущего значения+источника, см. правила в самом spec-файле.

## Как отвечать

По образцу `QA_COORDINATION.md`: сменить статус на `CLAIMED` перед началом
работы, `FIXED` — после правки с указанием файла/строки/источника,
`RECHECKED` — после независимой машинной проверки. Не редактировать
`data/all_projects_layer.json` / `data/coworking_202606.json` напрямую в
процессе активной сессии Claude — сначала синхронизация здесь.
