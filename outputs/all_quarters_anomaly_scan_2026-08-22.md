# Скан выбросов по ВСЕМ кварталам (17 buildings_*, 17 lots_*, 16 rent_lots_*, 10 coworking_*), 2026-08-22

Продолжение `outputs/q2_2026_anomaly_scan_2026-08-22.md` — та же методика
(цена vs медиана, gla>gba, total=price×area, координаты вне региона,
vacancy>seats), применена ко всей истории кварталов, не только Q2 2026.

**Ничего в данных этим сканом не менялось** — только находки.

## Найдено 65 сигналов, сводятся к 3 темам

### 1. STONE Дмитровская, Q1 2024 — ✅ ИСПРАВЛЕНО 2026-08-22 (интерполяция по соседним кварталам)

- 41 лот на этажах 9–13 (SD-901…SD-1314) имели `price=5000` при медиане по
  этому же зданию **296 000** (этажи 3 в том же файле — нормальные цены
  290 000–368 000).
- **Уточнение (2026-08-22):** предположение о повреждённой кодировке поля
  `scheme` было ошибочным — это оказался артефакт консольного вывода
  (cp1251/cp866) при первом просмотре, сам файл в порядке. Единственная
  реальная проблема — поле `price`.
- **Метод исправления (по прямой инструкции пользователя — сопоставить лоты
  по названию/площади/этажу/метражу с предыдущими кварталами):** у STONE
  Дмитровская есть история в 202212/202305/202308/202311 (до) и
  202410/202412 (после) Q1 2024. Все 41 «плохих» блока (SD-901 и т.д.)
  нашлись **в обоих** соседних кварталах — 202311 (до) и 202410 (после),
  с чистым линейным трендом цены (~+9500 руб/м²/квартал — совпадает с общим
  темпом роста STONE, видимым во всех остальных зданиях). Цена
  интерполирована как среднее между 202311 и 202410 для каждого блока;
  `total` пересчитан как `price × area`. Старое значение (5000) сохранено
  в `prev_price`, источник — в `price_fix_source` каждой строки.
- **Отдельно — 1 мусорная строка** `{"block": "5003121000", "floor": 19473,
  "area": 256914.2, "price": 0}`: не сопоставляется ни с одним лотом ни в
  одном соседнем квартале — не является реальным лотом (число 5003121000 —
  утёкший ID из исходной таблицы). **НЕ удалена и не заполнена цифрой** —
  помечена `qa_flag` с объяснением, решение по удалению — отдельно.
- **Дополнительно найдено и исправлено:** сводные `price`/`volume` здания в
  `buildings_202403.json` были заражены той же мусорной строкой —
  `price=256914` дословно совпадал с усечённой мусорной `area=256914.2`.
  Пересчитано как взвешенное среднее по 89 реальным (не мусорным) лотам →
  **338 587 руб/м²**. `volume` не изменился (совпал с суммой реальных
  площадей и до, и после — не был заражён, несмотря на схожесть с мусорным
  `floor=19473`).
- **Новая находка, НЕ исправлено:** поле `weight` в `buildings_202403.json`
  у STONE Дмитровская = `5003121000.0` — то же число, что и мусорный
  `block`. НО у всех остальных STONE-зданий в этом же квартальном файле
  `weight` тоже хранит подобные многомиллиардные числа (2,5–8,2 млрд) без
  видимой связи с мусорными строками в их лотах — похоже на отдельный,
  более широкий баг во всём файле `buildings_202403.json` (или во всём
  пайплайне сборки), не специфичный для одной битой строки. Вне рамок этой
  правки — не трогал, оставляю как наводку для следующего захода/Codex.
- Regression: `tests/test_stone_dmitrovskaya_price_fix.py` (8 тестов).
