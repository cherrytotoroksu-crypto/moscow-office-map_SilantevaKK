# Единый кодификатор: blueprint до начала миграции

## Цель

Один канонический реестр всех офисных проектов из общей карты и квартальных сводов, с устойчивыми ID. Квартал и канал не создают новый проект: они являются наблюдениями/предложением проекта.

## Границы сущностей

`project` — девелоперский проект/комплекс.

`building` — отдельный корпус, башня или адрес внутри проекта.

`lot` — конкретный лот в квартальном срезе.

`offer_observation` — наличие и параметры предложения в конкретном квартале и канале: sale / rent / flexible-office.

`source_record` — исходная строка с сохранением имени, источника и даты.

## ID

- `PRJ-0001` … — единый ID проекта; после публикации не переиспользуется.
- `BLD-PRJ-0001-01` … — корпус/башня проекта.
- `LOT-<quarter>-<channel>-...` — лот/наблюдение; не использовать проектный номер повторно.
- Старые `OBJ-*`, `canonical_project_id`, IDs сводов и внешних слоёв сохраняются в `legacy_ids`.

## Правила слияния

Автослияние запрещено при одном совпадении имени, адреса или координаты. Слияние проекта допускается только при подтверждении минимум двух независимых признаков (адрес/девелопер, официальный сайт, GLA/GBA, внешний источник) и журналируется. Разные корпуса одного проекта никогда не схлопываются в один корпус.

## Этапы

1. Инвентаризация всех источников по периодам и каналам; исправить отсутствующие/пустые файлы.
2. Нормализация имени, адреса, девелопера, GLA/GBA и дат без удаления исходных значений.
3. Кандидатное сопоставление проектов; ручная очередь конфликтов.
4. Построение `project` → `building` → `lot` → `offer_observation`.
5. QA: полнота, дубли, география, площади, каналы, историческая стабильность ID.
6. Генерация единого кодификатора и адаптеров для старых квартальных файлов.
7. Только после QA — обновление карты и онлайн-таблиц.

## Обязательные поля provenance

Для каждого нормализованного поля: `source`, `source_date`, `verification_status`, `confidence`, `verified_at`, `legacy_ids`, `review_notes`. GLA является основной площадью; GBA не подставляется вместо неё.

## Запреты до завершения QA

- не перенумеровывать старые ID вручную;
- не считать строки каналов отдельными проектами;
- не объединять River Park, STONE, iCITY и аналогичные комплексы без уровня корпуса;
- не удалять спорные записи — помещать в очередь `needs_review`;
- не менять `data/building_dates.json`.
