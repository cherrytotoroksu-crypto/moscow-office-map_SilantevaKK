## Коворкинги (coworking_202606.json)

**78 из 79** записей без класса здания. Причина двойная:
1. `index.html:1308` резолвит класс коворкинга джойном `bc` (имя здания-хоста)
   против `buildingsData` (продажа) по точному совпадению строки — для сетевых
   операторов имя здания в файле коворкингов почти никогда не совпадает
   дословно с именем в продажной базе.
2. Даже там, где здание УЖЕ есть в `data/all_projects_layer.json` (проверено
   19 записей SOK/Refolio/Deworkacy/Workki по адресу) — `cls` там тоже `None`.
   Это не только баг джойна в JS, это пробел в первичных данных.

## Правила для продолжения

- НЕ угадывать класс по названию сети (одна сеть держит площадки в разных
  по классу зданиях — уже видно на SOK: B и A в разных точках).
- Каждое подтверждение — с источником (офиц. сайт сети / 2GIS/ЦИАН) в
  `qa_notes`, как для Remain-конфликтов.
- Расхождение адреса (как Складочная 8 / Красносельский тупик 17) — не
  чинить исправлением `cls`, сначала перепроверить сам адрес.
- `data/building_dates.json` не менять.
