# Спецификация: редактор картосхем

Дата: 2026-07-30. Статус: **только спецификация, не реализуется** (по прямому
требованию задачи — «пока не реализуй сложное редактирование»). Портировано
из `ONLINE_MAP_SCHEME_EDITOR_SPEC_2026-07-29.md` (Codex) с уточнением полей
под точную схему `all_projects_layer` этого проекта.

## Идея

Отдельный режим «Редактор картосхем». Не редактирует исходные квартальные
лоты и не редактирует канонический реестр проектов напрямую. Пользователь
создаёт версию схемы, выбирает срез данных, размещает объекты/подписи,
сохраняет как воспроизводимую публикацию.

Ключевой принцип: **данные проекта и визуальная композиция разделены**.
Изменение названия/статуса/площади в базе обновляет схему после пересборки;
ручное положение подписи или цвет слоя не теряется.

## Требуемые из задачи функции

1. **Выбор проекта** — по `canonical_project_id`/`canonical_building_id` из
   общего реестра (см. `ALL_PROJECTS_LAYER_SPEC_2026-07-30.md`).
2. **Изменение координаты, статуса, цвета и подписи** — но: изменение
   координаты в редакторе схемы — это `scheme_position`, НЕ перезапись
   `latitude`/`longitude` канонической записи (см. «Важное различие» ниже).
   Изменение `project_status`/`construction_status` из редактора схемы —
   тоже не прямая запись в канонический реестр, а предложение правки,
   уходящее в отдельный журнал/на подтверждение (см. режим «Рецензия»).
3. **Предварительный просмотр** — режим «Просмотр» ниже.
4. **Журнал изменений** — обязательное поле версии (см. «Версионирование»).
5. **Экспорт обновлённого слоя** — PNG/SVG/PDF, и GeoJSON только для
   разрешённых (не приватных) геометрий.
6. **Обязательное подтверждение перед публикацией** — режим «Публикация»
   ниже, публикация фиксирует версию без права редактирования опубликованной
   версии напрямую.

## Режимы работы

1. **Просмотр** — карта/таблицы как сейчас, изменить данные нельзя.
2. **Редактор** — выбор квартала/среза, слоёв, подписей, цветов, группировки,
   размещения. Панель свойств показывает происхождение значения:
   каноническое поле / квартальный срез / внешний источник / ручная
   аннотация — не смешивать в одну строку без пометки источника.
3. **Рецензия** — diff между версиями (добавлено/удалено/перемещено/
   переименовано). Другой пользователь принимает или отклоняет.
4. **Публикация** — версия фиксируется, получает ссылку, доступна только для
   просмотра. Публикация НЕ меняет канонический реестр.

## Рабочая область

Центр — карта/картосхема; слева — дерево слоёв; справа — свойства
выбранного объекта; сверху — срез/версия/режим/сохранение/публикация; снизу
— журнал предупреждений и число выбранных объектов.

## Слои (минимум)

Все офисные проекты; текущий квартал; прошлый квартал (для сравнения);
проектируемые/строящиеся; введённые; статус предложения; девелоперы; деловые
районы/кольца; ручные зоны и аннотации; легенда и подписи. Слой «Все офисные
проекты» не включает автоматически детали приватных лотов.

## Связь с данными (структура объекта схемы)

Каждый объект на схеме хранит ссылку на `canonical_project_id`/
`canonical_building_id` (те же ID, что в `all_projects_layer`). Ручная
фигура без проекта — `annotation_id` с обязательной подписью автора/
источника. Схема хранит НЕ копию базы, а ссылки + позиционирование:

```json
{
  "scheme_id": "q2-2026-market-map",
  "base_snapshot": "202606",
  "data_version": "...",
  "visible_layers": ["all_projects", "construction_stage"],
  "objects": [{
    "ref_type": "canonical_project",
    "ref_id": "chalet-pyatnitskaya-40",
    "x": 0, "y": 0,
    "label": {"visible": true, "dx": 12, "dy": -8},
    "style": {"color_token": "series-2", "size": "medium"}
  }],
  "annotations": [],
  "legend": {},
  "status": "draft",
  "updated_at": "2026-07-30"
}
```

(`base_snapshot` использует формат `YYYYMM`, как существующие квартальные
файлы проекта, а не `YYYY-Q#` из черновика Codex — для согласованности с
`data/buildings_202606.json` и т.п.)

## Важное различие: карта и картосхема

- **Географическая карта** — проверенные координаты (`latitude`/`longitude`
  из `all_projects_layer`) и масштаб.
- **Картосхема** — вручную раздвинутые точки/подписи/зоны, со ссылкой на
  реальное положение.

Для каждого объекта — два раздельных положения: `geo_position` (из
канонических данных) и `scheme_position` (ручное). **Нельзя подменять
координаты карты ручным положением на схеме** — это инвариант, который
должен проверяться перед сохранением (см. ниже).

## Проверки перед сохранением

- нет объектов без канонического ID, если не помечены как ручные аннотации;
- координаты и положение на схеме не перепутаны (`geo_position` ≠
  `scheme_position` смешение);
- нет двух разных проектов с одинаковым устойчивым идентификатором;
- цвета/подписи соответствуют выбранной легенде;
- квартал/дата среза явно указаны;
- приватные поля (`public_visibility=internal_only`, `qa_notes`,
  сырые Remain-наблюдения) не попали в публичную версию;
- источник и уровень доверия доступны при открытии карточки объекта;
- изменения канонических данных после создания схемы — предупреждение, не
  тихое применение.

## Версионирование

Хранить: автора, время, исходный срез/версию данных, список изменений,
статус `draft`/`review`/`published`/`archived`. Опубликованную схему
редактировать напрямую нельзя — только новая версия/черновик. Конфликты —
блокировка/предупреждение + сравнение версий.

## Публикация и доступ

Публичная схема содержит только разрешённые поля; приватный черновик требует
авторизации (эта задача не решает вопрос авторизации редактора — см.
открытые вопросы); ссылка на опубликованную схему — только просмотр; URL
кодирует `scheme_id`, версию, фильтры; экспорт — PNG/SVG/PDF (+ GeoJSON для
разрешённых геометрий) с подписью источника/квартала/даты/ограничений.

## Этапы внедрения

1. **Безопасный MVP** — просмотр слоёв, выбор квартала, авто-создание схемы
   из проектов, перетаскивание подписей, сохранение черновика, undo/redo,
   PNG/SVG.
2. **Работа с данными** — сравнение кварталов, стили по статусу/классу/
   девелоперу, группировка корпусов, предупреждения об изменившихся данных,
   ссылки на источники.
3. **Совместная работа** — роли viewer/editor/reviewer, комментарии, diff
   версий, согласование и публикация по ссылке.
4. **Расширенный редактор** — ручные зоны, сетка/привязки, авто-раскладка
   подписей, шаблоны, пакетный экспорт.

## Что не делать в первой версии

Не давать редактировать исходные лоты прямо на карте; не смешивать ручное
положение схемы с географическими координатами; не публиковать приватные
квартальные таблицы вместе с публичной схемой; не делать полноценный
GIS-редактор до проверки сценария MVP; не хранить копию всей базы в каждой
схеме.

## Нерешённые вопросы (специфичные для этого проекта)

1. **Авторизация редактора/рецензента** — в проекте сейчас нет вообще
   никакой авторизации (публичная карта открыта всем по прямой ссылке,
   `SECURITY_AUDIT.md`). Редактор картосхем по своей природе требует хоть
   какого-то разграничения «кто может редактировать/публиковать» — это
   отдельное архитектурное решение (простая парольная защита одного
   маршрута? отдельный доступ через GitHub? не решаю сам).
2. **Где хранить версии схем** — отдельные JSON-файлы в git (аналогично
   текущему подходу с `data/*.json`) или что-то ещё — не решено, вне
   объёма этой задачи (только спецификация).
