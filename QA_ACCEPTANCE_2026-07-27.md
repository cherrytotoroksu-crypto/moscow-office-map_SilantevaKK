## Новые задачи

### QA-008 — автоматический пересчёт геополей

После любого изменения `lat/lng` автоматически пересчитывать:

- административный округ — из `data/ao.geojson`;
- район — из `data/mo.geojson`;
- зону — из `data/zones.geojson` с единой таблицей преобразования кодов;
- субрынок — из `data/submarkets.geojson`;
- деловой район — только по документированному источнику и алгоритму.

Результат point-in-polygon должен проверяться тестом. Ручное сохранение геополей от старой точки запрещено.

### QA-009 — исторические координаты Regus Greenwood

Исправить ту же неверную точку в кварталах 202407–202512 и в геокеше либо явно объявить исторические снимки неизменяемыми. Выбор политики должен быть записан в документации.

### QA-010 — каноническая идентичность коворкинга и предложения

Определить разные ключи:

- `location_id` — стабильная площадка;
- `offer_id` или `row_id` — отдельный блок/предложение;
- квартал — версия наблюдения.

До утверждения схемы нельзя назначать новые ID просто по свободным числовым промежуткам, кроме уже принятого аварийного исправления QA-002.

### QA-011 — единый источник и генерация classifier.html

`classifier.html` должен генерироваться из канонических JSON и справочников. Ручное параллельное исправление JSON и HTML создаёт рассинхронизацию и прекращается после появления генератора.

## Рабочий протокол Claude Code ↔ Codex

1. Работать пакетами не более 5–10 находок.
2. Перед началом пакета записывать `base_commit`, список QA-ID и роль исполнителя.
3. Одновременно производственные данные меняет только один исполнитель. По умолчанию это Claude Code; Codex в этот момент работает только на чтение.
4. Исполнитель меняет канонические источники и прикладывает подтверждения, но не объявляет результат завершённым.
5. Статус после правки: `FIXED_PENDING_REVIEW`.
6. Codex запускает независимую машинную проверку и точечную сверку источников. Возможные результаты: `ACCEPTED` или `NEEDS_REWORK`.
7. Производные файлы создаются генератором после исправления источников и проверяются на совпадение.
8. Коммит и отправка в `main` выполняются только после `ACCEPTED`. Исключение — отдельная аварийная ветка с явным разрешением пользователя.
9. Если Claude Code недоступен, роль исполнителя может перейти Codex только после записи `role_switch` в handoff-файле; одновременное редактирование запрещено.

## Обязательная автоматическая приёмка

- все JSON разбираются без ошибок;
- в актуальном квартале нет повторяющихся `row_id`;
- нет известных координат-заглушек и `0,0`;
- адрес, название БЦ и координаты относятся к одной сущности;
- округ, район, зона и субрынок заново вычислены по координатам;
- скачки одной сущности между кварталами либо объяснены, либо заблокированы;
- `classifier.html` совпадает с каноническими источниками;
- изменения ограничены заявленными QA-ID;
- рабочее дерево чистое после принятого коммита.
