# Спецификация: онлайн-таблицы

Дата: 2026-07-30. Статус: спецификация. Основано на
`ONLINE_TABLES_AND_STATUS_SPEC_2026-07-29.md` (Codex), дополнено конкретными
списками колонок под существующие файлы проекта (`data/buildings_*.json`,
`data/lots_*.json`, `data/rent_lots_*.json`, `data/coworking_*.json`) и новый
`data/schema/all_projects_layer.schema.json`.

## Общий принцип

Настоящие интерактивные таблицы внутри приложения (не статичный HTML/картинка).
Сортировка/фильтрация — на данных текущего представления, не меняя исходные
JSON/квартальные снимки. Для таблицы «Все лоты» — виртуализация строк
(потенциально тысячи строк на квартал).

Обязательный набор возможностей для всех 4 таблиц: сортировка А→Я/Я→А/по
числам по каждому столбцу; фильтр по значениям столбца; поиск по всей
таблице; множественный выбор значений; фильтр «пусто/не пусто»; закрепление
первого столбца; выбор видимых столбцов; сброс фильтров; экспорт
отфильтрованного представления в CSV/XLSX; подпись среза (квартал/дата
обновления/число строк); колонки `Источник`/`Дата проверки`/`Уровень доверия`
в каждом представлении.

`entity_grain`).

## 3. Девелоперы квартала

Агрегат по `data/buildings_{quarter}.json`, группировка ТОЛЬКО по проектам,
входящим в выбранный квартал (не по всему кодификатору).

| Колонка | Как считается |
|---|---|
| Девелопер | группировка |
| Проектов в квартале | count(distinct `name`/`canonical_project_id`) |
| GBA суммарно | sum(`gba`) |
| Объём на продажу суммарно | sum(`volume`) |
| Лотов суммарно | sum(`lots`) |
| Ср. взвешенная цена | sum(`price`×`volume`)/sum(`volume`) |
| Классы (перечень) | distinct(`cls`) по проектам девелопера |

## 4. Все лоты квартала

Источник: `data/lots_{quarter}.json` (продажа) + `data/rent_lots_{quarter}.json`
(аренда) + `data/coworking_{quarter}.json` (коворкинг) — **разные типы строк**,
не единая денормализованная таблица без указания канала.

| Колонка | Продажа (`lots_*.json`) | Аренда (`rent_lots_*.json`) | Коворкинг (`coworking_*.json`) |
|---|---|---|---|
| Здание | ключ объекта в файле | ключ объекта в файле | `name`/`bc` |
| Канал | константа `sale` | константа `rent` | константа `coworking` |
| Этаж | `floor` | `floor` | — |
| Площадь | `area`/`size` | `area`/`size` | — |
| Цена/ставка | `price`, `total` | `rate`, `opex`, `nds` | `rate` |
| Планировка | `scheme` | `finish` | — |
| Корпус | `block` | `block` | — |
| Сеть/адрес | — | — | `network`, `address`, `district` |
| Мест всего/вакантно | — | — | `seats`, `vacancy` |

Переключатель канала — вкладки или взаимоисключающий переключатель (см.
раздел 6 `ONLINE_TABLES_AND_STATUS_SPEC` Codex), НЕ общий столбец-фильтр —
чтобы физически исключить смешение продажи/аренды/коворкинга в одном
представлении по ошибке.

## Дополнительные функции для квартальных таблиц (кроме кодификатора)

Обязательные (порт из Codex, без изменений по существу):
переключатель квартала в одном месте страницы; режим сравнения двух
кварталов (`значение`/`предыдущий квартал`/`изменение`/`% изменения`);
сохранённые представления фильтров; ссылка на текущий вид, кодирующая
квартал/фильтры/сортировку/видимые столбцы в URL; итоговая строка
(количество/площадь/сумма/средневзвешенная цена); группировка по проекту с
раскрытием лотов/корпусов; карточка источника по строке; предупреждения
качества («площадь агрегатная», «нет детальных лотов», «канал не
подтверждён», «объект изменился с прошлого квартала»); защита от смешения
каналов отдельными вкладками.

Второй этап: подсветка новых/исчезнувших/изменившихся проектов; фильтр
«только изменения»; закрепление ID+названия при горизонтальной прокрутке;
группировка по девелоперу/району/классу; пресеты («Все продажи»,
«Строящиеся», «Введённые», «Без источника», «Только изменения»); экспорт
манифеста применённых фильтров; режим «расхождения с предыдущим кварталом»;
отдельная отметка «нет данных» vs `0`; дата среза + дата обновления
источника в шапке.

## Рекомендуемый порядок внедрения (из Codex, не меняю)

Сначала: выбор квартала, сравнение кварталов, итоговая строка, сохранение
URL, группировка, ссылки на источники. Затем: подсветка изменений, пресеты,
расширенный экспорт.

## Реализация (2026-07-31) — `codifier.html`

Все 4 таблицы реализованы как отдельная страница `codifier.html`, не
затрагивающая `index.html`/`classifier.html`/production-данные. Join между
`buildings_*.json` и общим кодификатором по `canonical_project_id`
реализован **на чтении, в браузере** (сопоставление по имени/исходному
имени в JS), а не добавлением поля в саму production-схему — снимает
открытый вопрос №1 ниже без изменения `data/buildings_*.json`. Вместо
виртуализации строк — постраничная навигация (50/100/250/1000 строк на
страницу, переключаемо) с итоговой строкой, считающейся по ПОЛНОЙ
отфильтрованной выборке, а не по текущей странице.
